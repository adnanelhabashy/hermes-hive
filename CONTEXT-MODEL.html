Hive Skills & Context — The Right Model

Should all hive agents share ONE skills folder? How to give them the least context, most capability — grounded in research + Hermes mechanics.

01The thing most people miss: Hermes skills are lazy-loaded

A skills folder does not dump every skill's content into every turn. Each turn only carries a tiny index — skill name + a ~57-char description. The full SKILL.md body loads only when the agent calls skill_view and actually needs it.

So "sharing the full skills folder" costs far less than you'd fear. The real per-turn cost is the index (name + description per skill), not the bodies. The bodies are pulled on demand, like a library you browse rather than a book you carry.

The catch: a big index is still a tax on attention. ~150 skills × ~50 tokens ≈ 7,500 tokens of pure menu every turn — and every token depletes the model's attention budget (Anthropic: "context rot").

03The model: three layers, not one or the other

The answer to "share one folder or not" is both, deliberately tiered. Capability comes from the shared base; focus comes from per-role specialization; shared working state comes from the hive itself.

🟦 LAYER 1 — Shared Fleet Base SHARED
One curated folder of ~15–25 universal skills every agent might reach for: pdfdocxweb-extractemailstripeterminal-patterns …
Why: "lightest yet most capable" — this is the answer to your question. Small index (low attention tax), full bodies on demand (full capability). Agents share a vocabulary (both know pdf-engine), so agent→agent instructions can reference skills by name.
↑ per-profile override
⬛ LAYER 2 — Per-Role Specialty CURATED PER PROFILE
Each agent keeps its own role skills, matching its job: @closer → outreach@builder → code-review@analyst → research/llm-wiki
Why: bounds each agent's menu to its specialty (Vercel: "bounded per agent, split by specialty"). Keeps selection accurate and the menu small. Role skills are already wired per-profile in Hermes.
↑ shared working memory
🟪 LAYER 3 — Hive Working Memory SHARED (dynamic)
The hive's digest + shared scratchpad — injected every turn, capped, append-only.
Why: this is where "agents take scoped instructions from other agents" actually lives. It's the dynamic shared context that adapts to the mission, instead of a static skill dump. Small, explicit, current — not a library.

04Share one folder vs. curated tiers — the honest tradeoff

One shared folder (all 150) WORSE

  • + Every agent has every capability
  • + Zero team-setup config
  • – Huge index tax every turn (×N agents = amplified)
  • – Selection accuracy drops → wrong-skill picks
  • – Collision risk (pdf vs pdf-engine vs pdf-generator)
  • – "Context rot" — noise crowds signal

Curated tiers (base + role + hive) BEST

  • + Full capability where it matters (shared base)
  • + Small, accurate menu per agent (role skills)
  • + Shared, adaptive state (hive scratchpad)
  • + Shared vocabulary for agent→agent handoffs
  • – One-time curation cost (pick the ~20 base)
  • – Naming discipline required

05Verdict

Yes to sharing — but a curated "fleet base" (~20 skills), not the full 150-skill dump.

Sharing is right because skills are lazy-loaded: the bodies are free per-turn, and the shared index gives every agent a common vocabulary so agent→agent instructions can name skills precisely. But the index must stay tight, because attention is the real currency and a 150-item menu degrades selection (Anthropic) and costs ~15× in multi-agent setups (Vercel).

The deeper unlock — your instinct, confirmed by the research — is that agent→agent instruction is the new context: a tightly-scoped handoff from @builder to @researcher carries more usable signal than a huge static prompt. The hive's relay grammar + digest + scratchpad are this mechanism, and they're already built.

06What this means for the hive (concrete)

  • Shared base folder → point hive members at one curated ~/.hermes/skills/fleet/ (or a shared skills dir) so they all see the same ~20 universal skills.
  • Role skills stay per-profile → each agent keeps its specialty; the base stays universal.
  • Hive handoff discipline → teach agents (already in the room brief): when you relay to a teammate, include a 1–3 line status + what you need, never a raw dump. Small handoffs = fewer failures (36.9% stat).
  • Scratchpad = shared working memory → keep it capped (we cap at 8k) and current; it's the dynamic context that replaces static bloat.
  • Index hygiene → skill descriptions should be action-prefixed ("Use when…") and ≤57 chars, so selection is accurate.
  • On-demand, not everything → agents load skills lazily via skill_view; never assume the full folder is "in context."
